# 核验与交付

## 文本核验

- 将跨镜对白依顺序拼接，和采用稿逐字核对；仅忽略明确无语义的排版空白。保留说话人、词序、数字和标点，不用“意思相同”掩盖改词。
- 每段直接绑定全部核心资产，逐镜写到标点位置和俯视机位。可选效果图不可替换控制图。
- 镜内发声/动作时段不超过镜长；段内时间连续、段时长等于镜长总和；实际自然试读另行核验。
- 入口/出口逐镜、逐段对照：位置、姿态、持物手、物品数量、视线和动作完成状态。
- 逐镜核必须可见/明确画外人物、露出与进出时机；核相机朝向对应背景。固定全景不附加无理由后拉，跟拍不误成持续拉远，遮挡物件不靠搬位置同框。
- 剪辑镜头与模型生成段分别核，低于模型下限的镜头不能当独立提交段；截图范围不代表步进或参考上限。见[直接参考生成与实片迭代](direct-reference-production.md)。
- 标注当前平台素材/时长限制是否已读取。没有读取界面/文档时，不宣称“可直接提交某平台”。

结构化计划可运行：

```bash
python scripts/validate_plan.py examples/two-person-plan.json
python scripts/validate_plan.py your-plan.json --check-files
```

脚本只检查角色/资产映射、核心输入、标点与机位字段、时间和对白拼接；不会判断真实图片是否换脸、示意点位是否正确、机位是否可达或成片是否好笑。未加`--check-files`时不检查引用图片在磁盘上存在。

## 视觉与媒体核验

看实际图检查身份特征、服装、位置、手物接触、正反打背景和光向。图解检查文字可读与点号一致。大图可先用长边≤1280的轻量预览，细节有疑问再局部查看；只看预览不能说全尺寸逐像素通过。

生成视频后才检查口型、实际台词、动作衔接、重复动作、声纹、节奏及反应触发。静态图正确不能推定视频正确，文字时长正确不能推定自然试读正确。

区分稀疏抽帧、局部密帧、连续播放和音频听辨的覆盖。每秒一帧可初检人数构图，不据此确认打击次数/接触/同步；按问题补证据。用户接受的小穿帮记录保留，后续稿不要求已接受片段批量重做。

## 最小交付

按任务需要提供：完整稿、可独立复制的分段稿、素材文件名与职责、导演说明/接续状态、核验范围及待办。已有图像原件保留，不用预览覆盖；修订稿保留版本并指向当前使用版。

对话历史、用户身份照片、API配置与密钥不是Skill模板的一部分。公开版本使用自创文本和结构示例；未包含的媒体明确说明，不伪造端到端示例已经生成。
